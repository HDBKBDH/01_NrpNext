# 多站点隔离架构

> 每个项目一个独立 site（独立数据库），物理隔离，互不干扰。

## 架构

```
                    ┌─────────────────────────────────┐
                    │  莱卡云 (110.42.60.173)         │
                    │  frappe_docker 同一套 bench      │
                    ├─────────────────────────────────┤
                    │  MariaDB                        │
                    │   ├── _945e68dd4d82c4d9  (erp.motitoo.com)  ← J2C_ISTK
                    │   └── <新库名>          (c2j.xxx.com)      ← C2J_ISTK
                    │  Redis (cache/queue 共用，key 带 site 前缀) │
                    ├─────────────────────────────────┤
                    │  apps/                          │
                    │   ├── j2c_istk    ← J2C 项目专用 app │
                    │   └── c2j_istk    ← C2J 项目专用 app │
                    └─────────────────────────────────┘
```

## 为什么用「独立 site」而不是「同一个 site 多个 app」

Frappe 的 `Item` / `Item Group` / `UOM` / `Brand` / `Warehouse` /
`Company` / `Serial No` / `Bin` 都是**全站共享的全局表**，没有 app 归属字段。
同站点多 app 会共用同一批主数据 —— 隔离做不到。

独立 site = 独立数据库 = 上面所有表物理分开，天然隔离。

## 隔离效果

| 层面 | 隔离方式 | 状态 |
|---|---|---|
| 数据库 | 每 site 一个库 | ✅ 物理隔离 |
| 主数据 | 各库独立 | ✅ 物理隔离 |
| 库存/单据 | 各库独立 | ✅ 物理隔离 |
| 侧栏/菜单 | 各自的 Module + Dock + Workspace | ✅ Frappe 原生 |
| 品类语义标识 | 根节点用项目名（J2C_ISTK / C2J_ISTK） | ✅ 额外标识 |

## 项目标识约定

每个项目：
- App 名：`j2c_istk` / `c2j_istk` / ...（小写，Python 包名限制）
- Module 名：`J2C_ISTK` / `C2J_ISTK` / ...（大写，显示 + 存储）
- Workspace 名：同 Module 名
- 品类根节点：同 Module 名
- Company：`ISOTENKAI` / `C2J_ISTK` / ...

## 建新项目站点

```bash
# 1. 先把 app 代码部署到 /opt/erp/apps/<app名>
# 2. 跑建站脚本
/opt/erp/deploy/new_site.sh c2j.motitoo.com c2j_istk
```

脚本会：
1. 前置检查（站点不存在、app 已部署）
2. `bench new-site`（建库 + 装 app）
3. `bench migrate`（跑 app patch → 自动建 Company / Warehouse / 品类树 / UOM / Brand）
4. 打印验证结果和后续步骤

## 域名配置（域名确定后单独做）

```nginx
server {
    server_name c2j.motitoo.com;
    ...
    proxy_set_header Host $host;
    proxy_set_header X-Frappe-Site-Name c2j.motitoo.com;   # ← 关键
    ...
}
```

然后：
```bash
bench set-sites-frappe c2j.motitoo.com
```

## 已知约束

1. **Item 仍是 ERPNext 的** —— 每个 site 自己的库，天然隔离，但 J2C 站点必须装 erpnext app
2. **备份按库名全覆盖** —— 现有备份脚本 dump 所有库，新库自动包含
3. **Redis 共用** —— Frappe 的 cache key 带 site 前缀，逻辑上隔离
4. **app 代码共用 bench** —— `apps/` 目录共享，但每个 site 只 install 自己需要的 app
