## B 类：设计不符合业务现实

### 1. 散件采购模块有逻辑问题（用户反馈，待梳理）
**状态**：待处理
**发现时间**：2026-10-23 仓库管理梳理时
**用户原话**：「散件采购 这个模块 有逻辑问题 后续再改」

**已知的疑点**（待与用户确认真实流程）：
- `Trade Settings.default_warehouse` 现在指向 `BJ-CSRH - CSRH`，
  但散件采购是日本采购，入库仓应该是 `JP`。
  （用户说这个字段本身属于散件采购模块的逻辑问题的一部分）
- 散件采购单和拆解单是两套平行结构，都能直接产生商品明细和 SN
  → 一个零件从哪来，查不出来源类型
- 散件采购单缺供应商信息（supplier / supplier_type），
  而拆解单有 supplier_type（Company / Individual / Tourist）
  → 三类卖家（中古许可公司 / 个人无法开票 / 游客已退税）差异大
- 汇率字段两表不统一：拆解单 `settlement_rate` / 散件采购单 `exchange_rate`
  → 且没区分「交易日汇率」vs「结算汇率」

**处理前必须做的**：跟用户走一遍他的真实录入流程，再定改法。
不要凭字段结构猜。
